开放平台接口全局约定

开放平台接口统一区分通信层与业务层：HTTP 状态码只表达请求是否到达并处理完成，业务成败由 JSON 响应体中的 code 字段表达。

HTTP 200 + 业务 code 异步任务统一状态枚举

通信层与统一响应

开放平台接口严格区分 HTTP 状态码（通信层） 与 JSON code 字段（业务层）。调用方必须读取 code 判断业务成功或失败，不能只依赖 HTTP 状态码。

HTTP 状态码（通信层）

HTTP含义
200请求已到达服务端并完成处理（所有开放平台接口均为此状态）
非开放平台接口（如分集解析、DOCX 上传等）仍可能使用 4xx / 5xx 表达错误，不在本文档范围内。

序号值含义

2VALIDATION_ERROR框架级请求校验失败，data.errors 为字段级错误列表

④ 路由与重名规则

多个渠道提供同名模型，服务端按以下规则决定走哪个渠道：

  • **显式传了 llm_provider**：一律按 llm_provider 路由。共享命名的模型（gpt-*、claude-*、gemini-3.8-flash）搭配任一提供它的渠道都不判冲突。
  • **只传 llm_model**：按下表从模型名推断渠道。
  • 因此 **MegaAI / 灵感鸭 / 联通 / STA1N / barael / 星网AI 六个渠道必须显式传 llm_provider**；即刻的 gpt-5.6-* 也须显式传 llm_provider=jikexin。
  • 显式传入的 provider 与模型归属明显不一致（例如 llm_provider=glm + llm_model=deepseek-v4-pro）时，发起接口返回 PARAM_ERROR。

⑤ 服务端默认与自动降级

  • 不传 llm_* 时，服务端默认使用 **DeepSeek deepseek-v4-pro（非思考）**。
  • 首选渠道出现网络类错误（超时 / DNS / TLS / 代理 / 5xx / 429）或空响应时，按固定顺序降级到已显式开启的备用渠道；当前部署默认仅 GLM（ALLOW_GLM_FALLBACK=1）参与降级。
  • 其余渠道（含豆包 / Qwen / Claude 及所有中转站渠道）默认不参与降级链，需在 .env 显式设置对应 ALLOW_*_FALLBACK=1（开关名见 ③）。代理 403 的临时补链同样遵循该开关。
  • 业务类错误（401 / 400 参数错误 / 余额不足）不会自动切换渠道，保留原始错误便于排查（小生自身的 401 / 余额不足属于下条「官方保底」范围，不切渠道、只在本渠道内改发官方）。
  • 小生 → 官方保底（2026-10-20 起，仅 deepseek / glm）：这两个渠道经小生调用；小生本身不可用时，同模型、同参数改发官方一次，发生在渠道内部，先于上面的降级链。
    • 切官方：连接 / DNS / TLS / 代理失败、5xx、429 限流、401 / 402 / 403、余额不足、空返回、网关报错包类假成功；
    • 不切：超时（避免耗时翻倍）、400 参数错误、内容审核拦截、结构化拒答；
    • 熔断：同一渠道连续 3 次切官方后，5 分钟内直接走官方；到期先试小生，成功即恢复；
    • 走官方的调用 billing.calls[].provider 记为 deepseek / glm，按官方原价计费；官方也失败时返回官方的错误，再按降级链处理。

visual-workbench（视觉工作台）

一个统一异步流程，顺序执行四个节点（补全视觉证据 → 规划美术风格 → 生成资产提示词 → 质检与优化资产提示词）。节点结果写入任务目录，中途失败保留已成功节点；可通过 request_id + retry_node 从指定节点重试。对外任务 ID 为 request_id；通信层与业务层遵循上方「全局定义」。

模块 visual-workbench 前缀 /api/v1/visual-workbench/jobs 接口 B1 / B2 / B3

通用规则（B1–B3 共享）

本节定义流程节点、分路与重试语义。通信层、业务状态码、任务级与子任务级状态枚举见上方「全局定义」，此处不重复。

流程节点

节点 retry_node中文名说明

重试语义

重试通过 B1 传 request_id + retry_node 发起，创建新任务并复用已成功的上游节点结果，清空并重跑该节点及其下游。

retry_node默认行为（refresh_upstream: false）
enrich_assets复用原始输入，重跑后清空 style_bible、asset_prompts
style_bible使用最新 enrich_assets 结果，重跑后清空 asset_prompts
asset_prompts使用最新 enrich_assets + style_bible，仅重跑提示词节点

refresh_upstream：布尔，默认 false。置 true 时忽略上表的「复用」语义，执行起点回到 enrich_assets，全流程重跑。当失败由上游输入决定时（例如资产数据缺口导致提示词节点完整性校验始终不通过），默认重试会沿用同一份上游结果、必然复现同一失败，此时应传 refresh_upstream: true，或重新走一次首次提交。该字段只在重试请求中生效，首次提交时忽略。

T3. 重试子任务

/api/v1/pro/trajectory-planning/jobs/{request_id}/retry

用途简介

同 request_id 原地重试或追加执行子任务；已成功子任务结果默认保留，仅重跑 retry_tasks 中指定的项。动线子任务支持按批重试（retry_batch_indices）。

Request Body

参数结构
Request Body object application/json iRequest BodyT3 重试请求体；指定要重跑的子任务，可选按动线批次重试。
retry_tasks string[] 必填 待重试子任务 iretry_tasks1–3 项；合法值同 T1 run_tasks，可重试失败或跳过的子任务。
retry_batch_indices integer[] 可选 动线失败批号 iretry_batch_indices仅当 retry_tasks 包含 trajectory_plan 时有效；批号从 1 开始，例 [1, 3, 5]。省略时服务端重跑当前所有 failed 批。
force_retry_succeeded boolean 可选 强制重跑已成功子任务 iforce_retry_succeeded默认 false；设为 true 时允许覆盖已成功子任务结果。

重试规则

当前子任务状态默认行为
failed可重试；成功后 T2 的 result 补充或更新对应键
skipped可追加执行；该子任务会加入当前任务并重新入队
succeeded默认不可重试；需传 force_retry_succeeded=true
pending / running任务处于 queued / running 时不可重试

Response Body data

参数结构
data object T3 重试受理响应 idata仅表示重试请求已受理；调用方需要继续轮询 T2 获取最终结果。
request_id string 任务 ID irequest_id与原任务相同，重试不会生成新的任务 ID。
status string 任务状态 istatus重试受理后通常为 queued，最终状态以 T2 查询为准。

对接推荐（默认）

状态与子任务

任务级 status 见「全局定义 · 状态枚举」。本模块 tasks[] 固定含 characters / scenes / props 三项；每项含子任务状态与 batch_total / batch_succeeded / batch_failed 批次进度。

task_name中文名写入 result 的方式
characters角色抽取合并进 result.master_assets（asset_type=character）
scenes场景抽取合并进 result.master_assets（asset_type=scene）
props道具抽取合并进 result.master_assets（asset_type=prop）

result 返回规则

任务查询接口的 LLM 计费字段为 data.billing（任意终态携带，同 job 重试为累计口径），见「基本约定 · LLM 计费字段 billing」。

  • 进行中：result 固定为 null；以 tasks[] 观察三路子任务进度。
  • 终态：result 含 master_assets、markdown、variant_warnings（公开契约不含落盘路径与内部统计）。
  • 部分成功：status=partial_succeeded；已成功类型的资产仍保留在 result.master_assets 中。
  • 取消：若取消前 pipeline 已产出片段，E2 仍可能返回非空 result。

Pro 道具资产边界（三种模式一致）

oneshot、loop_1pass、loop_3way 三种 extraction_mode 使用相同的真人剧 Pro 道具判定标准，仅执行与合并方式不同：

本接口只服务真人剧 Pro，因此不接收 production_mode。底层使用统一的内容驱动资产规则；三种 extraction_mode 仅改变执行与合并方式，角色、场景、道具的判定标准完全一致。
  • key_props 是供 AI 复核的候选线索，不是必须入库清单。
  • 优先保留需要跨镜头或跨集维持同一外观、状态或归属的可辨识道具。跨镜一致性是软判断，服务端不会仅因为出现次数达到某个阈值就机械放行。
  • 常规手机、文件、无特征工具等可由视频模型自动生成的普通物件，通常不进入资产总表；仅在其外观身份、状态延续或剧情证据必须保持一致时保留。
  • 建筑、房间、桥梁、栈桥、道路、舞台、码头、船坞等固定空间或基础设施属于场景/场景组成，不得同时作为 prop。即使其被指向、拆除或推动剧情，也不改变类型。拆下的普通结构件默认也不建资产；只有部件明确脱离原空间、具有独特稳定外观，并在后续镜头中需要追踪同一实体时，才可进入道具候选。
  • 最终 master_assets 中 asset_type=prop 的总数最多 15 个；超过时优先保留跨镜一致性风险最高的道具。

对接推荐（默认）

final_video_prompt 自动诊断与优化

旧调用方无需改造：本集所有分镜组成功生成后，服务端会结合整集分镜表与全部 V1 先做一次整集诊断，再并发优化确有问题的分镜组。可选 audience_type 省略时默认 female；不新增响应字段，终态仍直接读取 result.episodes[].scenes[].final_video_prompt。
  • 优化成功时 final_video_prompt 为 V2；无需优化、诊断异常或单组优化失败时保留 V1。
  • audience_type=male 只在原分镜已有对应内容时，软偏好拍清“作用路径 → 可见结果 → 局势变化”，不强加战斗、能力或胜负。

重试对接（G3）

重试模型（重要）：每集分镜生成分五步——前四步「场划分 → 全局连续画面链规划 → 扩写分镜组 → Skill 召回」以集为粒度做断点缓存，重试时不重算；只有第五步「分镜组生成」支持按分镜组重试。
因此 G3 标准对接为按分镜组重试 retry_shot_groups：读取 G2 失败分镜组的 shot_id，仅重生成这些分镜组的视频提示词，复用该集前四步缓存，最省成本。目标组生成新 V1 后会重新执行整集诊断，不会将旧 V2 叠加优化；未重跑组在本轮无需优化或优化失败时保留旧的正式 final_video_prompt。G3 沿用 G1 建任务时冻结的 audience_type 与 resolution，不接受受众或画幅覆盖。仅当某集前四步（规划阶段）尚未完成或失败、还没有分镜组可重试时，才用空 body {} 按集断点续跑该集。不提供整集强制重跑（成本过高）。G3 同样沿用冻结的 duration_tier；生成重试会按集让过期的 result.h3 失效，并在重试跑完后只为"完整成功但尚无 H3 条目"的集增量补算 H3（仅 15s 档 + include_h3=true 的任务）；H3 失败组或待补齐的集可传 retry_h3=true 做 H3-only 重试（先补齐缺失集、再原位重跑失败组，可配 llm_provider / llm_model 换源，写 H3 专用渠道）；生成重试同渠道确定性失败时也可配 llm_provider / llm_model 换模型（覆盖持久化为新的任务级渠道，后续生成重试沿用），详见 G3。

POST

G3. 重试

/api/v1/live-action/shot-group-generation/jobs/{request_id}/retry

对接推荐（默认 · 按分镜组重试）

标准对接：
  1. G2 轮询至 status 为 failed / partial_succeeded（非 running）
  2. 读取 G2 tasks[].episodes[].steps[step_name=shot_generate].failed_shot_groups[].shot_id
  3. POST …/jobs/{request_id}/retry，Body 传 retry_shot_groups
  4. 继续轮询同一 request_id，直至终态
仅重生成失败分镜组的视频提示词，复用该集前四步缓存。若某集前四步未完成或失败、暂无分镜组可重试，则用空 body {} 按集断点续跑该集。

运行机制（五步重试模型）

每集分镜生成分五步：前四步「场划分 → 全局连续画面链规划 → 扩写分镜组 → Skill 召回」以集为粒度做断点缓存，重试时不会重算已成功步骤；只有第五步「分镜组生成」支持按分镜组重试。G3 使用同一 request_id 原地重入队，不生成新任务 ID。retry_shot_groups 仅重生成指定分镜组（复用该集前四步缓存，对应节点 shot_generate）；目标组生成新 V1 后重新执行整集诊断，不将旧 V2 叠加优化，并在本轮优化失败时保留未重跑组的旧正式提示词。空 body {} 仅用于前四步未完成/失败时，按集断点续跑该集。不提供整集强制重跑（成本过高）。

用途简介

重试已进入终态的分镜组生成任务。标准对接为按分镜组重试 retry_shot_groups，仅重生成失败分镜组；前四步规划失败的集用空 body {} 按集断点续跑；15s 档 H3 失败组或待补齐的集可传 retry_h3=true 做 H3-only 重试（先补齐缺失集、再原位重跑失败组）。15s 档 + include_h3=true 的任务在生成重试跑完后按集增量补算 H3（只重算本轮被重跑过的集）。生成重试与 H3-only 重试均支持 llm_provider / llm_model 换模型：生成重试覆盖任务级渠道、H3-only 重试写 H3 专用渠道，均持久化、后续沿用（详见 Request Body 说明）。30s 档 + include_wan=true 的任务同理：生成重试后按集增量补算 Wan；Wan 失败组或待补齐的集可传 retry_wan=true 做 Wan-only 重试，换模型时写 Wan 专用渠道。

前置条件

任务须已进入终态（非 queued / running）。执行中重试返回 CONFLICT。

G4. 取消任务

/api/v1/live-action/shot-group-generation/jobs/{request_id}/cancel

用途简介

取消进行中的异步任务。无 Request Body；仅任务状态为 queued / running 时可取消。G4 返回 cancel_requested 表示受理，最终是否取消成功需再查 G2。

取消后如何继续（G3 续跑）

cancelled 是终态，但不必重新发起任务：对同一 request_id 调 G3 即可从断点续跑（不新建任务）。

做法行为
G3 空 body {}只重跑"失败 / 部分成功 / 未完成"的集；取消前已成功的集原样保留、不重跑（不产生重复计费），续跑跑完后与保留集合并返回
G3 + llm_provider / llm_model换模型续跑：只作用于本轮被重跑的集；已成功集仍是上一轮渠道的产物
已无待跑集（所有集都已成功）返回 CONFLICT（data.detail：没有可续跑的失败、部分成功或未完成分集），不会被当成整批重跑；确需重做用 episode_nos 显式指定集号，或重新发起 G1
取消生效边界：取消在"下一个进度回调点"生效（集级取消检查点）。已提交到并发池的镜头调用、以及正在进行的单次模型调用会自然结束（单次模型调用超时上限由服务端配置，默认 20 分钟），因此 G4 受理后任务可能短暂仍为 running；该窗口内 G3 返回 CONFLICT，必要时用 force=true 强制接管。续跑时，取消前已成功产出结果的集（result.episodes[] 中 status=succeeded）一律保留、不重跑；取消时正在跑的集不产出结果，由续跑补齐。

模块九 · super-narration-storyboard-generation

超级解说漫 · 分镜表格生成

输入整部解说漫剧本文本或 DOCX，解析锁定台词并按集并发补充视觉字段；输出与真人剧 Pro 剧本直连分镜表同构。

前缀 /api/v1/super-narration/storyboard-generation/jobsT1–T4 异步接口JSON / DOCX

通用规则（T1–T4）

单任务与 result

任务查询接口的 LLM 计费字段为 data.billing（任意终态携带，同 job 重试为累计口径），见「基本约定 · LLM 计费字段 billing」。

字段约定
tasks[0].task_name固定 super_narration_storyboard_generation
tasks[0].episode_*逐集总数、成功数和失败集号摘要
result进行中固定 null；终态含 episodes、errors、markdown

剧本解析与说话人归一化

script_format语义
auto自动识别剧本形态（默认）
full_read除“第 X 集”等集标题外，正文均作为朗读台词
tagged只把【旁白】/【对白】标记内容作为台词；场景、画面、系统提示、屏幕文字不作为台词

speaker_aliases 是用户选填的显式映射，例如 {"我":"沈烬"}；服务端不要求完整角色表，也不自动猜测身份。每行输出承载一条已解析台词，视觉生成不新增、改写或重复台词。

Pro 兼容结果

result.episodes[].normalized_script_rows[] 与模块八公开字段同构；story_blocks 为兼容字段，当前稳定返回空数组。调用方可复用 Pro 分镜表解析器。

模型、并发与幂等

max_workers 默认 8、范围 1～8。T1 支持服务端默认模型，也可选择固定为非思考调用的 deepseek-v4-pro / deepseek-v4-flash；DeepSeek 在 llm_max_tokens=0 时与 GPT-5 输出预算配置对齐（当前为 32768），T3 沿用 T1 配置。数据库原子查找/创建保证并发同参提交只产生一个进行中任务；复用方得到相同 request_id 与 reused=true，force=true 强制新建。

模块十 · super-narration-shot-group-generation

超级解说漫 · 分镜组生成

消费按集分镜表，复用真人短剧分镜组管线，同时注入隔离的 Super 提示词与 near-30 软时长策略；输出 scenes 与真人短剧完全同构。

前缀 /api/v1/super-narration/shot-group-generation/jobsT1–T4 异步接口资产每集必填且逐集隔离

通用规则（T1–T4）

script_rows 对接

audience_type 可选，取值 female / male / general，省略时默认 female。male 只在原分镜已有对应内容时，软偏好拍清“作用路径 → 可见结果 → 局势变化”，不强加战斗、能力或胜负。resolution 可选且默认 9:16，仅作为成片尺寸元数据保留，不参与分镜表归一化、V1、最终提示词或 V2 创作。两个字段都不改台词、分组、时长、资产或响应结构。

把模块九 T2 result.episodes[].normalized_script_rows 政名为本模块 T1 的 episodes[].script_rows；行内字段可直接复用。接口不拉取上游 request_id，也不接受完整上游 result。每行 dialogue 必须非空；缺省 estimated_duration 按锁定台词估算。

逐集资产隔离

episodes[].assets 每集必填且至少 1 项，每项 image_url 必填且 trim 后非空。每集只读取本集资产，不回退到其它集；角色资产可带 voice_url。

任务级 LLM、Super 提示词与 near-30

本模块支持 llm_provider、llm_model、llm_max_tokens、llm_timeout_ms，不传时使用服务端默认 LLM。
  • 可选渠道：deepseek / doubao / apiyi / gemini / jikexin / glm / megaby / linguanya / liantong / sta1n / barael / xingwangai；模型取值与路由/重名规则统一见 全局定义 · LLM 调用方式。
  • 显式覆盖贯穿规划、资产筛选、逐组生成、合规改写、V2 诊断/改写与后续重试；只作用于当前任务，并发任务不串用。
  • 显式覆盖不可用或渠道-模型冲突时返回 PARAM_ERROR，不静默回退默认模型。
  • 本模块没有 shot_density 或剧情/台词策略覆盖入参；服务端固定使用“较多（随时长动态）”密度与隔离的 Super 提示词。

非特殊情况下每个分镜组尽量靠近 30 秒，但只做提示词层软引导，不增加机械校验、自动回退或空台词补写；剧情边界等特殊情况可以更短。prompt_requirements 只追加用户约束，不替换 Super 专用提示词，也不影响模块七。

剧情结构、台词语言和台词保留策略在内部分别固定为 strict、follow_script、preserve_full。单集规划时长只汇总各行 estimated_duration；该值省略或为 0 时先按锁定台词估算。内部 90 秒稳定回落不是请求参数。

任务查询接口的 LLM 计费字段为 data.billing（任意终态携带，同 job 重试为累计口径），见「基本约定 · LLM 计费字段 billing」。

缓存重试

T3. 重试

/api/v1/super-narration/shot-group-generation/jobs/{request_id}/retry

用途简介

与真人短剧 G3 共享重试语义，但继续使用隔离的 Super 提示词与 near-30 软策略。空对象自动续跑；可整集或按缓存重试指定组。

retry_shot_groups 非空时优先，episode_nos 被忽略。按组重试复用前四步缓存并只更新指定组；缺缓存或 ID 不存在时必须改为整集重跑。T3 不接受受众或画幅覆盖，始终沿用 T1 冻结值。
